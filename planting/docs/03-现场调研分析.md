# 现场调研分析

> **项目**：禾丰种植合作社 · 种植灌溉与农事记录
> **阶段**：02 现场调研 ｜ 3 项任务（角色访谈 / 还原现状流程 / 四来源收敛与材料核对）｜ 得分 72 / 72 / 72
> **方法**：六角色访谈（36 个访谈点）+ 四来源材料核对（Buyer 业务目标 / Brief 书面范围 / Industry 技术可行性 / Operator 现场故障）
> **结论**：问题成立、值得立项，但**基线、验收口径与责任边界三处缺口未补前不得进入方案设计**
> **资料性质**：合成训练案例；不代表真实授权、业务执行或客户验收

## 4. 保留的分歧（不抹平）

1. **优化目标分歧**：田间按地块实际状况判断，经营按用水成本考核（`f50`）。同一笔建议交接时容易互相推责。→ 验收同时看「用水」与「作物状态」两条硬线（`f02`）。
2. **完成口径分歧**：唐映秋要求接手人确认（`f23`），叶书要求逐笔统计、通知数不算（`f51`）。→ 二者不冲突：一个管动作留痕，一个管统计口径，必须同时落地。
3. **兜底能力分歧**：快照能保证数据可用（`f35`），但不能保证读数准确（`f31`）。→ 分两条线：可用性（快照/去重）与准确性（埋深校准/单位/异常判定）。
4. **验收严格度**：顾明岚给三条硬线（`f02`），傅景追加安全约束与停止条件（`f42`）。→ 合并为一张验收清单，停止条件单列。

## 6. 分析结论

**问题成立**，三条理由：

1. **有真实异常事件**，不是「想上 AI」的想象（`f10`、`f11`）；
2. **有明确边界**：只读、不自动控制泵阀、异常不驱动执行（`f05`、`f32`、`f40`）；
3. **有可判定的验收方向**：4 地块、用水降且作物不恶化、异常全人工核验（`f02`）。

**但价值还不能承诺**，两条理由：

1. 全部损失数据为单岗位口径且未经样本验证，`f01` 已明确「节点耗时未分别量出」；
2. 用水口径与基期未定，验收结论不可复现。

**因此本阶段的正确结论是**：立项方向成立 → 先在 4 个地块做只读试点 + 30 天基线取样 → 用样本回写第 4 节的损失评估，再讨论方案设计。

**本阶段不做的事**：不设计自动灌溉、不做泵阀联动、不做跨系统写操作、不做人员考核口径。

## 7. 方法局限

| 局限 | 说明 | 影响 |
| --- | --- | --- |
| 单一来源 | 36 条事实均为角色口述 | 结论只能到「方向可信」，不能到「金额已核实」 |
| 缺原始凭证 | 无单据、日志、制度原文 | 无法判断陈述与真实流程的偏差 |
| 样本未采集 | 未做 30 天连续取样 | 返工率、核验耗时全部空缺 |
| 案例为合成 | 平台合成案例 | 不构成对真实客户的承诺 |
