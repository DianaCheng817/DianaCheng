# 项目一页纸 · 禾丰种植合作社 · 种植灌溉与农事记录

> 用途：FDE 报价实战课「项目一页纸」自选项目填写件。五个关键数决定后面的 Token、服务器配置与 ROI 口径，数值均取自本项目访谈事实（`fxx` 编号见 `02-访谈记录.md`）。
> 配套文件：`项目一页纸-已填写.csv`（按课程模板回填，可直接提交）、`项目一页纸-纯文本.txt`（纯文本版，便于整段复制）。

## 一、五要素

| 项目项 | 填写内容 | 为什么先定它 |
| --- | --- | --- |
| 客户是谁 | 禾丰种植合作社，负责人顾明岚牵头（合作社负责人）；全社 24 个地块，首期 4 个地块试点（f02）；首期预算上限 8 万元，超出走额外审批（f03、f04） | 决定报价模式与谈判对象：决策人单一（顾明岚），但预算需额外审批 |
| 多少人用 | 6 个关键角色：顾明岚（负责人）、林亦舟（田间技术员）、唐映秋（农事计划员）、秦芮（农业物联工程师）、傅景（农产品质控员）、叶书（基地经营代表）；实际开通账号人数未采集，待核实 | 决定并发与服务口径：6 角色中真正高频使用的是技术员与计划员 |
| 每天多少量 | 24 个地块每天共 60 次观测，人工汇总约 90 分钟（f12）；异常复核与交接的发生频次尚未采样，待核实 | Token 与算力测算的起点：观测次数本身量级极小，真正的消耗在异常复核的对话轮次 |
| 数据在哪 | 三套系统：农业物联平台、气象服务、农事表；账号权限彼此独立，没有统一的业务状态视图；传感器埋深与校准记录不完整、地块面积单位不统一（f30、f31） | 决定数据与对接工作量：三源对齐本身就要投入工作量，且无统一主键 |
| 能不能上云 | 首期按本地部署走：模型与知识图谱跑在基地本地，数据不出场；能否上云取决于三套系统的数据归属与对外开放授权，访谈未覆盖，待核实。系统只读，不自动控制泵阀（f05、f32、f52） | 一票否决项：决定走云端 API 还是本地私有化 |

## 二、待核实项（填写时留空或标注，不得当作已确认事实）

1. 三套系统各自的部署位置：厂商云 / 合作社内网 / 本地服务器，以及农业物联平台是否允许读数同步出基地。
2. 异常复核与交接的日均发生次数（决定对话轮次与 Token 量）。
3. 实际开通账号人数与并发峰值。

## 三、口径说明

- 8 万元是首期预算上限，属成本侧约束；收益侧目前只有「每亩用水 −12%」「旱情发现 2 天→半天」两个访谈目标值（f00），不是实测基线，报价时不得当作已实现收益。
- 若上云授权无法确认，报价按本地私有化路径报，不按云端 API 路径报。
