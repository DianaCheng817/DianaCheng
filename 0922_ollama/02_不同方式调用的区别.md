# 0922 作业②：不同方式调用的区别 —— Ollama API / OpenAI Chat Completions / OpenAI Responses / Anthropic Messages

> 学号：f25011102 ｜ 日期：2026-10-02

这四种都是"让程序调用大模型"的接口协议，区别在于**接口设计哲学、端点路径、消息结构、生态归属**。下面从 4 个维度对比，并给出代码样例。

## 一、一句话总览

| 调用方式 | 归属/厂商 | 典型端点 | 定位 | 本机 Ollama 能否直接跑 |
|---|---|---|---|---|
| **Ollama API** | Ollama（本地推理引擎） | `/api/generate`、`/api/chat` | 本地模型的一手原生接口，最简 | ✅ 原生支持 |
| **OpenAI Chat Completions** | OpenAI 定义，事实标准 | `/v1/chat/completions` | 多轮对话（messages 数组），生态最广 | ✅ Ollama 内置兼容层 |
| **OpenAI Responses** | OpenAI 新一代统一 API | `/v1/responses` | 把对话/工具/记忆统一成"状态化交互"，面向 Agent | ⚠️ 云上（OpenAI/百炼等），Ollama 暂无 |
| **Anthropic Messages** | Anthropic（Claude） | `/v1/messages` | Claude 专用消息接口，system 独立字段、流式友好 | ⚠️ 云上（Claude/部分国产平台兼容），Ollama 暂无 |

## 二、逐个拆解

### 1. Ollama API（本地原生）
- 端点：`GET /api/tags`（看模型）、`POST /api/generate`（一问一答）、`POST /api/chat`（多轮对话）、`POST /api/embed`（向量）……
- 特点：专门为"本机推理"设计，返回 `response`/`message.content`，自带 `total_duration`、`eval_count` 等推理性能指标；`stream:true` 支持流式。
- 适用：本地开发、离线、隐私场景；想省 token 费（本地模型不花钱）。
- 示例：
  ```bash
  curl http://127.0.0.1:11434/api/generate \
    -d '{"model":"qwen3:0.6b","prompt":"你好","stream":false}'
  ```

### 2. OpenAI Chat Completions（事实标准）
- 端点：`/v1/chat/completions`；请求体核心是 `messages: [{role: system/user/assistant/tool, content}]`。
- 特点：**无状态**——每次请求把整段历史都发过去；业界兼容性最强（OpenAI、千帆、百炼、通义、Ollama、vLLM……全都认这个协议）。
- 适用：几乎所有场景的"默认选择"；本地 Ollama 也支持，等于"同一套代码，云端/本地无缝切换"。
- 示例（Ollama 上直接跑）：
  ```python
  from openai import OpenAI
  client = OpenAI(base_url="http://127.0.0.1:11434/v1", api_key="ollama")
  r = client.chat.completions.create(model="qwen3:0.6b",
      messages=[{"role": "user", "content": "你好"}])
  print(r.choices[0].message.content)
  ```

### 3. OpenAI Responses（新一代统一 API）
- 端点：`/v1/responses`；请求体是 `input`（可以是文本/消息/工具结果），配合 `tools`、`store`（服务端记忆）等。
- 特点：**状态化**——服务端替你管理上下文和工具调用结果，一次 `responses.create` 就能处理"多步工具调用"；Chat Completions 偏"对话"，Responses 偏"Agent/任务"。
- 适用：OpenAI 系新项目、Agent 编排；国内百炼/千帆的"应用级兼容模式"也提供类似体验。
- 示例（伪代码）：
  ```python
  client = OpenAI(api_key=..., base_url="https://dashscope.aliyuncs.com/api/v2/apps/protocols/compatible-mode/v1")
  r = client.responses.create(model="qwen3.5-plus", input="你是谁？")
  print(r.output_text)
  ```

### 4. Anthropic Messages（Claude 系）
- 端点：`/v1/messages`；`system` 是**独立顶层字段**（不混在 messages 里），角色是 `user/assistant`，用 `content` 块数组（可含文本/图片/工具结果）。
- 特点：对**长上下文与流式**体验优化好；Claude 生态（含 Claude Code 类工具）主要用这套；部分国产平台提供"Anthropic 兼容模式"。
- 示例（伪代码）：
  ```python
  import anthropic
  client = anthropic.Anthropic(api_key="...")
  r = client.messages.create(model="claude-3-5-sonnet",
      max_tokens=1024,
      system="你是一个助手",
      messages=[{"role": "user", "content": "你好"}])
  print(r.content[0].text)
  ```

## 三、横向对比表（给"提交格子"用的一句话版本）

| 对比项 | Ollama API | OpenAI Chat Completions | OpenAI Responses | Anthropic Messages |
|---|---|---|---|---|
| 设计定位 | 本地推理引擎的原生接口 | 通用多轮对话标准 | 状态化 Agent/任务接口 | Claude 专用消息接口 |
| 核心参数 | prompt 或 messages | messages（system/user/assistant/tool） | input + tools + store | system 独立 + messages |
| 状态管理 | 无（历史由调用方维护） | 无（历史由调用方维护） | 有（服务端记忆/上下文） | 无（历史由调用方维护） |
| 工具调用 | 支持 tools（OpenAI 格式） | 支持 function calling | 原生 tool_use 流程 | 原生 tool_use |
| 流式 | stream:true | stream:true | 支持 | 支持 |
| 本机 Ollama 可用 | ✅ | ✅（兼容层） | ❌（暂无） | ❌（暂无） |
| 生态 | 本地/离线 | 最广，处处兼容 | 新项目/Agent | Claude 系 |

## 四、结论（怎么选）

- **本地跑、不花钱** → Ollama API；
- **要通用、要切换云/本地** → OpenAI Chat Completions（兼容性之王）；
- **做 Agent、多步工具调用、要服务端记忆** → OpenAI Responses（或百炼应用兼容模式）；
- **用 Claude 系模型** → Anthropic Messages。
