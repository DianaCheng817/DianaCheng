# 校园音乐 App「我的歌单」——顺序表实现与性能实测

**数据结构课程作业** · 成御萌 · f25011102

用 Python 手写一个顺序表（数组）版的歌单结构，在 **10 万条数据**规模下实测各操作耗时与元素搬移次数，用真实测量数据验证 O(1) / O(n) 的理论复杂度。

## 功能接口

统一封装在 `MyPlaylist` 类中：

| 接口 | 理论复杂度 | 说明 |
| --- | --- | --- |
| `get(i)` | O(1) | 数组下标直读 |
| `insert(i, song)` | O(n) | 位置 i 插入需后移 i..n-1，搬移 n-i 个元素 |
| `remove(i)` | O(n) | 位置 i 删除需前移 i+1..n-1，搬移 n-1-i 个元素 |
| `indexOf(name)` | O(n) | 顺序扫描，最坏扫 n 次 |
| `size()` | O(1) | 返回当前元素个数 |
| `showAll()` | O(n) | 遍历输出全部歌曲 |

## 实测结果（节选）

表 1：四种操作单次耗时（μs）

| n | get | insert(中部) | remove(中部) | indexOf(最坏) | insert(尾部) |
| --- | --- | --- | --- | --- | --- |
| 100 | 1.1 | 14.6 | 14.8 | 7.5 | 1.0 |
| 1,000 | 1.1 | 280.8 | 298.7 | 133.7 | 1.3 |
| 10,000 | 1.5 | 2,574.6 | 2,683.9 | 1,396.2 | 1.2 |
| 100,000 | 1.4 | 27,063.5 | 26,621.4 | 14,568.3 | 3.3 |

结论：`get` 基本恒定在 1μs 左右（O(1) 成立）；`insert`/`remove`/`indexOf` 随 n 线性增长，10 万条时插入中部耗时约 27ms，与 O(n) 的搬移量吻合。
