# 0929 作业③：通过《ai-agent-book》说明该智能体的设计符合什么思想

> 学号：f25011102 ｜ 日期：2026-10-02
> 参考书：《深入理解 AI Agent：设计原理与工程实践》（bojieli/ai-agent-book，开源，v2.0）
> 在线阅读：https://bojieli.github.io/ai-agent-book/
> 被分析的智能体：百炼 FlowAgent 1.0 版"开源微专业学习助手"
> 流程：开始 → 大模型①（意图规划）→ 条件判断 → 工具（网页搜索）→ 大模型②（综合回答）→ 结束

---

## 一、这本书的核心公式

《ai-agent-book》开篇就用一个公式贯穿全书十章：

> **Agent = LLM + 上下文(Context) + 工具(Tools)**

作者强调：**"Harness（驾驭层）工程才是真正的竞争壁垒"**——把同样的模型接上不同的提示词、记忆、工具，
出来的 Agent 能力天差地别。我建的"开源微专业学习助手"正是这个公式的一次完整实践。

## 二、公式对照：我的智能体 = LLM + 上下文 + 工具

| 公式成分 | 对应我智能体里的东西 | 说明 |
|---|---|---|
| **LLM** | 大模型节点①（意图规划）+ 大模型节点②（综合回答） | 使用 qwen-plus，同一个模型被拆成两个角色 |
| **上下文 Context** | 每个节点的 System Prompt + 用户输入 +（搜索结果） | 角色、行为边界、回答风格全部由提示词定义 |
| **工具 Tools** | 条件判断节点 + 百炼内置"网页搜索"工具 | 模型不联网，但能**调用工具**联网再回答 |

这直接对应书中第 1 章：Agent 的能力上限由上下文和工具决定，而不是模型本身——所以我给两个大模型节点
分别写了"规划提示词"和"回答提示词"，这比换更大的模型更有效。

## 三、逐章印证（本书各章的设计思想如何体现在我的智能体中）

### Ch2 上下文工程（Context Engineering）—— 本设计最核心的体现
书里说：**上下文限制 Agent 能力**，上下文工程包括提示词工程、Agent Skills、上下文压缩等。
我的智能体做了三件事：
1. **提示词工程**：两个节点各配一套 System Prompt（规划器只输出 JSON，回答器规定结构/出处/初学者友好），
   这是"把模型调教成不同角色"的纯提示词手段；
2. **Agent Skills 思想**：书中把"技能说明书"归入上下文工程，和我假期作业里 `skill.md`（"遇到 XX 情况用 XX 命令"）
   是同一种思路——**用文字给模型配技能，而不是重训模型**；
3. **上下文中转**：大模型①的输出（JSON 关键词）作为大模型②的输入上下文，形成"规划信息在流程中流动"。

### Ch3 用户记忆与知识库（User Memory & Knowledge Bases）
书里讲 RAG、知识图谱让 Agent 拥有"私有知识"。我的智能体用了**外部知识获取**的轻量版：
"网页搜索"工具等价于一个实时 RAG 检索源；如果把课程资料（课堂笔记、文档）接入百炼**知识库节点**，
就升级成了标准的 RAG 设计——这是本设计预留的扩展点。

### Ch4 工具（Tools）—— MCP 与感知工具
书中把工具分成**感知类（perception）、执行类（execution）、协作类**三类，并介绍了 MCP 统一协议。
网页搜索就是典型的感知工具：让模型"看到"它训练数据截止日期之后的信息。若再接入 MCP server
（读本地文件、查数据库、操作浏览器），工具面还能继续扩大——我的流程把"是否用工具"交给条件判断，
体现书中"**工具使用要由模型按需决策**"的思想。

### Ch6 交互：扩展观察与行动空间
书中第 6 章讲异步、语音、Computer Use 等多模态交互。我的 streamlit 网页（作业②）就是"人机交互"的一环：
用户通过网页输入 → 智能体返回 → 网页展示，形成了闭环；若进一步把回答用语音播报、或让 Agent 控制本地工具，
就走向书中描述的"更大观察与行动空间"。

### Ch7 评估（Evaluating Agents）
书中强调：**把性能变成可比较的信号，用评估集选方案**。我在"在线测试"阶段用一组示例问题
（如"百炼和 ModelScope 有什么区别"）反复测试两个提示词版本，比较回答质量——这就是最小化的评估集实践；
发布后还可以沉淀真实问答作为回归测试集，防止改坏。

### Ch9 持续进化（Continual Evolution）
书中讲：从**执行轨迹中提取学习信号**，更新知识、指令、程序。百炼发布后的版本迭代正是这个思想：
每次真实用户问得不好，就改 Prompt 或加知识库发布新版本——Agent 不是一次成型，而是持续进化的。

### Ch10 多 Agent 协作（Multi-Agent Collaboration）
书中说"集体智能 > 个体"。我的双大模型节点（规划器 + 回答器）已经是一种**分工**；若把"规划"和"执行"
拆成两个独立智能体、共享上下文、各司其职，就升级成了书中的多 Agent 协作模式——这是未来可扩展方向。

### Ch1 驾驭层工程（Harness Engineering）
最后回到第 1 章：我的智能体没有微调任何模型（那是 Ch8 模型后训练的范畴，成本高），
**全部能力来自流程编排（Harness）**：节点怎么连、提示词怎么写、工具何时调。这正是本书反复强调的
"**Agent 的智能来自工程而非模型**"的设计哲学。

## 四、一句话总结

> 我的百炼 FlowAgent 智能体，是《ai-agent-book》核心公式 **Agent = LLM + 上下文 + 工具**
> 的平台化落地：用**上下文工程**（两套系统提示词）塑造角色，用**感知工具**（网页搜索 + 可扩展 RAG/MCP）
> 弥补模型知识局限，用**评估与版本迭代**驱动持续进化——智能不来自模型本身，而来自围绕模型的驾驭层设计。
